# Как мы работаем с ИИ

Код в этом проекте пишут ИИ-ассистенты, а мы ставим задачи, проверяем результат и исправляем ошибки. Жюри оценивает не только кабинет, но и то, как шла работа с нейросетями. Поэтому всё, что для этого нужно, записываем сразу, а не вспоминаем в последний день.

## Инструменты

| Инструмент | Для чего | Кто пользуется |
|---|---|---|
| | | |

Сюда попадает всё: агенты для кода, чаты, генераторы картинок, сервисы для дизайна и видео, IDE. Для описания процесса нужен полный перечень и для чего использован каждый.

## Что сохраняем

| Что | Куда |
|---|---|
| что сделал ИИ в конкретной ветке | блок "Что сделал ИИ" в описании PR |
| удачные и важные промпты | [prompts/](prompts/), по файлу на промпт |
| ошибки агентов и что с ними сделали | [log.md](log.md) |
| скриншоты важных шагов, удачные и неудачные варианты | общая папка на диске (ссылку держим в чате команды, не здесь) |

Правило простое. Открыл PR, значит заполнил блок "Что сделал ИИ". Агент ошибся, значит появилась запись в журнале. Получился хороший промпт, значит он лёг в `prompts/`.

## Правила для агентов

Все правила лежат в одном файле, [AGENTS.md](../../AGENTS.md) в корне репозитория. Claude Code (от версии 2.1.277), Codex, Cursor и Copilot находят его сами. Gemini CLI по умолчанию ищет `GEMINI.md`, поэтому ему AGENTS.md указан в `.gemini/settings.json`.

Не создавайте в репозитории `CLAUDE.md` и `CLAUDE.local.md`. Если любой из них есть, Claude Code читает его вместо AGENTS.md, и общие правила молча перестают работать.

## Как ставим задачу агенту

Хороший промпт отвечает на пять вопросов. Шаблон можно копировать как есть:

```
Контекст: что за раздел, какие файлы уже есть, ссылки на docs.
Задача: что именно сделать, одной-двумя фразами.
Ограничения: что трогать нельзя, какие правила из AGENTS.md особенно важны.
Как проверить: какие тесты должны пройти, что открыть руками, на какой ширине экрана.
Что вернуть: список изменённых файлов, что не получилось, текст для блока "Что сделал ИИ" в описании PR.
```

Большую задачу сначала просим разбить на шаги и показать план, и только после согласования пусть пишет код.

## Как проверяем

Работу агента проверяем делом: тесты и CI, запуск, сценарий на телефоне. Для отдельных проверок есть субагенты Claude Code в `.claude/agents/`:

| Субагент | Что проверяет | Когда звать |
|---|---|---|
| `security-auditor` | доступ к чужим данным, вход, секреты, заголовки | перед влитием PR с новыми эндпоинтами и перед сдачей |
| `ui-auditor` | вёрстку на 360 px, единый стиль, состояния экранов, доступность | после нового экрана и перед финальной полировкой |

Находки субагентов тоже проверяем руками: ИИ ошибается в обе стороны, может и пропустить дыру, и найти несуществующую.

## Ошибки агентов

Каждая ошибка, которая повторилась хотя бы дважды, превращается в правило в разделе "Правила из наших ошибок" в [AGENTS.md](../../AGENTS.md). В журнале при этом отмечаем, какое правило появилось. Так видно, что работа с агентами со временем становится точнее, и это хорошо смотрится в описании процесса.
