# Промпт для задач на бэкенд

- Агент и модель: Claude (chat или Claude Code)
- Дата обновления: 19.11.2026 (D7-04, ретро)
- Этап: раздел кабинета

## Промпт

```
Прочитай AGENTS.md целиком. Прочитай docs/api.md, раздел, который касается задачи. Прочитай существующие файлы раздела Features/<Раздел>/ и соответствующие тесты.

Задача: <описание задачи>

Правила, которые особенно важны для задач на бэкенд:

1. Перед регистрацией эндпоинта сверь его путь с docs/api.md. Если путь в документе и в коде разошёлся, обнови документ явно и скажи об этом.

2. Не задавай Id = Guid.NewGuid() у сущности, которую добавляешь в коллекцию уже загруженного агрегата (EF сделает UPDATE вместо INSERT и упадёт с DbUpdateConcurrencyException). Пусть EF назначает ключ при SaveChanges.

3. Приведение типа пишем ( T )value — пробел внутри скобок, нет пробела снаружи. Формат проверяет CI.

4. Если пишешь миграцию вручную (нет dotnet), предупреди об этом сразу и попроси прогнать ModelMatchesLatestMigration перед мержем.

5. В начале каждого хода, где читаешь файлы или генерируешь код, одной фразой скажи, что делаешь сейчас.

6. На каждый новый эндпоинт с данными студента пишем интеграционный тест "другой студент получает 404".

7. После генерации кода скажи: что сделал, что не проверял (нет dotnet / не запускал), в чём не уверен.

Когда закончишь: напиши одной-двумя фразами текст для блока "Что сделал ИИ" в PR.
```

## Что получилось и что изменилось

Промпт написан по итогам D7-04 на основе 5 реальных ошибок из D7-01 и D7-02:

- правило про `Id = Guid.NewGuid()` появилось после падения `SecondChangeOfStaleRequestFailsOnVersion` в CI
- правило про пробелы в приведениях типа появилось после двух ошибок `dotnet format`
- правило про путь эндпоинта появилось после расхождения `/api/requests/types` и `/api/request-types`
- правило про ручные миграции появилось после снапшота D7-01, написанного без `dotnet`
- правило про «скажи, что делаешь» появилось после двух «продолжи» от пользователя

Подробности в `docs/ai/log.md`, раздел 2026-11-19.
