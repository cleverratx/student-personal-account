# Цифровой деканат

Цифровой деканат это личный кабинет студента, где в одном месте лежат расписание, оценки, справки и объявления деканата. Открывается с телефона, нужное находится за пару касаний. Мы делаем его вдвоём для номинации "Вайб-кодинг" на MGIMO AI Challenge 2026: код пишут ИИ-ассистенты, а мы ставим им задачи и проверяем, что получилось.

Это концепт для конкурса, а не официальный сервис какого-либо вуза. Все студенты, преподаватели, оценки и заявки здесь вымышленные.

Сейчас в репозитории лежат документация, правила для людей и агентов и CI. Код приложения появится следующим шагом.

## Как называем проект

| Где | Как пишем |
|---|---|
| в интерфейсе и текстах | Цифровой деканат (рабочее название) |
| репозиторий, Docker-образы, домен | `dekanat` |
| .NET: решение, проекты, пространства имён | `Dekanat` |

## Что внутри

| Раздел | Что там |
|---|---|
| Сегодня | Главный экран. Следующая пара, переносы, статусы заявок и ближайшие дедлайны, каждая карточка ведёт в свой раздел. |
| Расписание | Пары на день и на неделю с аудиторией и преподавателем. Перенос или отмену видно сразу, без открытия деталей. |
| Учёба | Оценки и зачёты по семестрам, сессия и короткий ответ на вопрос "как у меня дела". |
| Заявки | Справки и заявления онлайн. Статус видно как у посылки: подана, в работе, готова, выдана. |
| Уведомления | Объявления деканата, переносы пар и напоминания о дедлайнах. |
| Кабинет сотрудника | Здесь деканат проводит заявки по статусам, переносит пары и рассылает объявления. |

Сценарии, экраны и требования конкурса собраны в [docs/product.md](docs/product.md).

## Как это устроено

Бэкенд написан на ASP.NET Core (.NET 10) с PostgreSQL, фронт на React и TypeScript, а живёт всё это в Docker за nginx. Студент для сервера это тот, кто вошёл, а не id из адреса. Поэтому подставить в ссылку номер чужой заявки бесполезно, в ответ придёт 404. Пароли хранятся только хешами, а ключи от внешних сервисов лежат в переменных окружения на сервере и в браузер не попадают. Подробнее в [docs/architecture.md](docs/architecture.md).

## Быстрый старт

Каркаса приложения пока нет. Когда он появится, всё будет подниматься одной командой, нужен только Docker с Compose v2:

```bash
cp .env.example .env
docker compose up -d --build
```

## Как мы работаем

`main` всегда зелёный, поэтому вся работа идёт в коротких ветках вида `feat/schedule-week-view` и вливается через PR со squash. Коммиты и заголовок PR пишем по одному шаблону, например `feat(schedule): переносы пар видно прямо в карточке`. Перед слиянием должны пройти проверки `backend`, `frontend` и `conventions`. Все правила лежат в [docs/contributing.md](docs/contributing.md).

Лицензии у репозитория нет. По правилам конкурса исключительные права на решение и промпты переходят организатору.
