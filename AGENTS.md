# Правила для ИИ-агентов

Это единственный файл с правилами для всех агентов, с которыми мы работаем. Claude Code, Codex, Cursor и Copilot находят его сами, Gemini CLI через `.gemini/settings.json`. Если ты агент, прочитай его целиком до того, как что-то менять. Если правило мешает сделать задачу, не обходи его, а скажи об этом человеку.

## Что за проект

Цифровой деканат это личный кабинет студента: расписание, успеваемость, заявки и справки, уведомления и кабинет сотрудника деканата. Мы делаем его для конкурса MGIMO AI Challenge, и у конкурса есть жёсткие условия:

- только вымышленные данные. Не бери ФИО, оценки и номера зачёток реальных людей, даже для примеров и тестов
- на каждом экране входа и в профиле видно, что это концепт для конкурса, а не официальный сервис вуза
- логотип вуза не используем. Шрифты, иконки и картинки только с лицензией, которая это разрешает
- все сценарии работают на телефоне шириной от 360 px
- сайт открывается из России без VPN, поэтому внешние сервисы выбираем с этим условием

Подробнее про сценарии и экраны написано в [docs/product.md](docs/product.md), про устройство в [docs/architecture.md](docs/architecture.md).

## Где что лежит


Разделы бэкенда: `Auth`, `Profile`, `Schedule`, `Grades`, `Requests`, `Notifications`, `Today`, `Staff`. Полное дерево проекта лежит в [README.md](README.md#структура-проекта).

## Безопасность

Эти правила не нарушаем ни ради скорости, ни ради зелёного CI.

1. Студента берём только из сессии. В студенческих эндпоинтах нет `studentId` ни в пути, ни в query, ни в теле запроса.
2. Чужой ресурс отдаёт 404, а не 403, чтобы не выдавать, что он существует. Несуществующий отдаёт тот же 404.
3. Всё под `/api` по умолчанию требует входа. Анонимно доступны только вход и health, и это пишется явно через `AllowAnonymous()`.
4. `/api/staff/*` доступно только роли Staff.
5. Пароли храним только хешем через `PasswordHasher` из ASP.NET Core Identity. Пароли, cookie, токены и персональные данные в логи не пишем.
6. Секреты только в переменных окружения. `.env` не коммитим. Всё, что лежит во `frontend/`, видит браузер, поэтому ключей там быть не может.
7. Id заявок и других ресурсов, которые видны в адресе, делаем UUID.
8. На каждый новый эндпоинт с данными студента пишем интеграционный тест "другой студент получает 404".

## Как писать код

Бэкенд:

- код раздела живёт в своей папке `Features/<Раздел>/`: эндпоинт, DTO, валидация и логика рядом
- ошибки возвращаем в формате ProblemDetails, тексты ошибок для людей по-русски
- время храним в UTC, показываем во времени вуза
- предупреждения считаются ошибками, формат проверяет `dotnet format`
- миграции, которые уже в `main`, не меняем. Новое изменение схемы это новая миграция

Фронт:

- слои импортируют друг друга только сверху вниз: `app`, `pages`, `widgets`, `features`, `entities`, `shared`. Импорт через `index.ts` среза
- цвета, отступы и шрифты только из CSS-переменных дизайн-токенов, без захардкоженных значений
- у каждого экрана есть загрузка, ошибка с кнопкой "Повторить" и пустое состояние
- проверяй вёрстку на ширине 360 px, тап-зоны не меньше 44 px
- у кнопок-иконок есть `aria-label`, статус передаём не только цветом
- запросы к API пишем только через типизированный клиент из `shared/api`, руками пути не собираем

Если поменял эндпоинт: собери бэкенд (обновится `backend/openapi/openapi.json`), выполни `npm run api:generate` во `frontend/` и закоммить оба файла вместе с кодом.

## Git

Ветки, коммиты и PR называем по правилам из [docs/contributing.md](docs/contributing.md). Коротко:

- ветка `<тип>/<область>-<суть>`, например `feat/requests-status-timeline`
- коммит и PR `<тип>(<область>): <что сделано>`, после двоеточия по-русски, с маленькой буквы и без точки
- в `main` напрямую не пушим, PR вливает человек, когда проверки зелёные

## Чего не делать

- не менять `.github/rulesets/` и `.github/workflows/` без прямой просьбы
- не отключать, не удалять и не ослаблять тесты, чтобы CI стал зелёным. Если тест падает, разберись почему
- не придумывать эндпоинты и поля, которых нет в OpenAPI-документе
- не генерировать данные, похожие на реальных людей вуза
- не создавать `CLAUDE.md`, `CLAUDE.local.md` и `GEMINI.md`: все правила живут только здесь

## Когда закончил задачу

1. Прогони тесты и линтер той части, которую трогал.
2. Напиши человеку коротко: что сделал, как проверил и в чём не уверен.
3. Последней строкой дай готовый текст для блока "Что сделал ИИ" в описании PR, одной-двумя фразами.
4. Если человек поправил твою ошибку, предложи правило для раздела ниже, чтобы она не повторилась.
